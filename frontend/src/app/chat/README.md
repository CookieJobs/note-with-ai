# 聊天页面

[page.tsx](page.tsx) 组合真实会话、消息、输入和关联笔记，并向[工作区](../../components/workspace/README.md)登记历史与操作。生产页面复用侧栏 embedded `ChatHistoryPanel`，不再绘制第二列历史或旧顶部导航；隔离渲染保留独立导航 fallback。消息与来源展示见[共享组件](../../components/README.md)，服务端信任边界见[后端服务](../../../../backend/services/README.md)。

## 会话与 URL

普通进入 `/chat` 显示新对话，不自动打开首条缓存或历史。`?session=<id>` 等待当前用户的真实服务端历史，缓存只作暂显；读取失败可重试，失效 ID 明确报错并禁止发送，不回退到其他会话。主动选中其他会话、新建或成功删除 URL 所指会话时移除旧参数；删除失败保留参数和当前状态。

首次发送才创建普通本地会话，`committed` 后同步服务端 ID。历史合并保留请求期间新建且已保存的会话，以及服务端确认的正文和快照，过期加载不能覆盖它们。回复期间切换会话保留用户选择；等待和错误只显示在所属会话，单流未结束时不另启请求、不丢弃其他会话草稿。

从消息、绑定笔记入口、关联栏或抽屉点击笔记时，默认在聊天旁打开只读阅读面板，保留对话、草稿与当前 URL，不改变聊天绑定。面板读取最新保存的完整原文，替换相关笔记栏；只有“打开完整笔记”和关闭两个常规操作。窄于 1200px 时使用可关闭的阅读抽屉，支持 Esc、焦点约束和关闭后返回入口；切换用户或会话时关闭，旧请求不能覆盖当前笔记。加载、删除/无权读取与可重试失败分别呈现，不把聊天旧摘录冒充完整原文。

主动选择“打开完整笔记”时，才记录当前用户在本标签页中的会话 ID、标题、未发送草稿与阅读位置，并向笔记 URL 加入 `fromChat=<sessionId>`。笔记页显示固定返回栏，查看相关笔记仍保留同一来源；返回入口明确进入 `/chat?session=<sessionId>`。30 分钟内返回时消费一次，历史未到则等待对应会话，不换成另一条。恢复期间补载历史不自动滚到底部，主动发送、切换或新建后恢复正常滚动。修饰键/新标签页打开链接保持浏览器默认行为，不覆盖当前标签页的恢复快照。

## 笔记入口与流式状态

[startNoteConversation](../../services/noteConversation.ts) 保存明确选择的 `sourceNoteId` 与空 `messages`，得到有效服务端 ID 后才进入对话，不请求随机笔记或伪造 AI 开场。新绑定会话提供来源入口和提问提示；旧历史中的真实 AI 开场首问后收起，原消息和回答快照仍保留。每轮读取最新已保存文字，旧回答继续展示当轮 `sourceSnapshot`；发现线索的关联栏排除绑定笔记，无其他记录时不占右侧空间。

有效发送被接受时立即清空输入，失败仅在仍处于原会话且没有后来草稿时恢复问题；相同问题重试不重复追加用户消息。[useChatStream](../../hooks/useChatStream.ts) 只认服务端 `committed` 为保存成功；提前结束或无提交确认的部分回答不能冒充已保存。连续 60 秒无数据或总计 180 秒后解除加载，迟到响应不能覆盖后续请求，reader 清理不能阻塞界面恢复。

删除确认等待真实 Promise，期间禁止重复确认；失败保留历史、弹窗和重试入口。历史搜索仅覆盖已加载会话。布局与主题以 [DESIGN.md](../../../../DESIGN.md) 为准。

回归入口：[页面状态](page.test.tsx)、[流式提交](../../hooks/useChatStream.test.ts)、[会话与历史合并](../../hooks/useChatSession.test.ts)、[笔记绑定服务](../../services/noteConversation.test.ts)。执行结果与浏览器验收范围属于发布记录。

## 笔记发现入口

新对话建议区只显示 `NoteDiscoveryPanel` 的短卡。详情与历史在主内容区独立阅读，通过返回或浏览器后退回到原输入和入口焦点。读者可在详情核对原文、编辑成果草稿或继续探索；普通输入不绑定发现。选择“继续探索”后接纳 `/api/note-discoveries/:id/session` 返回的真实会话与已完成的行动承接。原新对话草稿留给下一次进入空白对话。创建期间锁定普通发送，阅读中返回或切换会话后，迟到的发现会话不会抢走用户当前选择。发现会话使用多篇来源提示，每轮展示服务端全部版本快照。缓存/远程历史保留 `sourceMode`、`discoveryId`、`selectedSourceIds` 与 `sourceSnapshots`，客户端 `/chat/save` 和聊天请求均剥除快照。发现后续提问使用同一标签页保留的请求标识处理不确定失败重试；服务端 `committed` 后清除该标识。

首次可见访问明确发送 `admit=true`，轮询、状态检查和可见性恢复均使用不进入调度的 `admit=false`；旧读取不能覆盖确认后的偏好更新。确定未发出的预算拒绝由服务端返回 `retryEligible` 与失败请求 ID，界面另给“额度恢复后重新尝试”操作；仅该明确操作携带 `retryOfRequestId`。服务端验证已持久化的预算拒绝及未发送事实，并由前次请求派生稳定新 ID。普通重发、断网、未知投递和处理中均核对原尝试，不依据错误文字或通用 503 更换标识。
