# 聊天页面

2026-10-20 流式可靠性修订：有效发送被接受时立即清空输入，不等待回答结束；失败时仅在仍处于原会话且没有后来草稿时恢复问题。所有会话均以服务端 `committed` 为保存成功依据，收到后立即结束等待；无提交确认的部分回答不会冒充已保存。请求在连续 60 秒无数据或总计 180 秒后解除加载，迟到响应不能覆盖下一次请求，reader 清理也不能阻塞界面恢复。

`page.tsx` 组合聊天历史、消息列表、输入框和相关笔记。普通进入页面时默认显示新对话；本地缓存与服务端历史记录只供用户主动选择，不自动打开第一条历史对话。从对话打开来源笔记时，会记录该用户在当前标签页中的会话、未发送草稿和阅读位置；30 分钟内返回时消费一次记录并恢复，历史尚未加载则等待对应会话，绝不替换成其他会话。右侧面板、窄桌面抽屉和消息内来源链接共用该恢复行为。首次发送消息时才创建本地会话，流式回复提交后同步当前会话的服务端 ID；用户在回复期间切换到其他会话时，保留用户的选择。

`chat.module.scss` 提供聊天页面布局及组件样式。`page.test.tsx` 覆盖缓存和异步历史加载、普通页面重新进入、来源往返恢复、主动选择与新建会话，以及首条回复提交前后历史请求返回的时序。历史合并保留请求期间新创建并保存的会话，避免过期响应覆盖新对话。恢复阅读位置期间，服务端历史补载不会触发自动滚到底部；主动发送、切换或新建会话后恢复正常滚动。

“从这条笔记聊起”将会话绑定到所选笔记，服务端确认保存后才展示开场。首问前，页面以“从一条笔记聊起”为标题，先展示标明出处的原文摘录，再展示带身份标识的 AI 开场提问；输入提示邀请用户回应或换个角度聊。首问后，顶部收为“正在讨论”和来源入口；每轮由服务端读取这篇笔记最新保存的文字。侧栏、窄桌面抽屉与计数只展示当前绑定笔记之外的关联记录，无其他记录时不占用右侧空间。原始来源数据仍保留，供标题与历史开场恢复使用。普通新对话不继承绑定，未绑定的对话提示通过单篇笔记入口开始。服务端保存的每条回答快照由 `ChatMessage` 展示，与用于发现线索的“相关笔记”分开。来源保存或读取失败时显示可读错误，保留提问和草稿；相同问题重试不会重复追加用户消息。绑定对话若流提前结束、未收到服务端提交，也按未保存处理并移除部分回答。历史合并保留服务端已接受的正文和版本快照，再补上本地尚未提交的尾部；同 ID 的流式提交也始终采用服务端会话。
