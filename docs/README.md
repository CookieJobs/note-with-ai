## Git 与归档

- 当前准则、公开可复现的开发/部署说明、关键设计决定和精选版本验收随代码进 Git。
- 已完成执行清单、重复旧方案和过期审查从当前目录移除；已提交内容仍可从 Git 历史追溯。
- 未提交旧实验或待清理资料先移入仓库外私有归档；不为了消除 untracked 状态而盲目提交。
- 代理账本、额度与进程记录、原始运行日志、测试账号、凭据和数据库/镜像备份不作为公开文档。`.gitignore` 只管未跟踪文件，不能替代对已跟踪文件的收录检查。
- 截图保留与版本报告对应的必要证据，检查个人内容和账号信息；不提交整批未审查的截图目录。
- 修改或删除文档时同步处理链接；使用仓库相对路径，避免本机绝对地址、`file://` 或依赖私有账本才能理解的结论。

## 更新触发

产品规则变更更新 PRODUCT/架构，界面规则变更更新 DESIGN，运行配置变更更新 AI/部署说明；重要发布追加精简版本记录。引用与代码不一致时，先核实实际实现和用户批准范围，再更新文档，不能按旧文档重新恢复已退役功能。
