# NoteWithAI 工作区整体 UI 迁移 Spec

日期：2026-10-24。历史状态：**本次迁移已实施、经用户确认并完成发布**，对应主分支版本 `72dc316`。本文保留当时批准的迁移范围与验收合同；当前产品和工程规范以根目录 [DESIGN.md](../../../DESIGN.md)、[ARCHITECTURE_DOCUMENTATION.md](../../../ARCHITECTURE_DOCUMENTATION.md) 和 [PRODUCT.md](../../../PRODUCT.md) 为准。发布结果及验证边界见 [版本摘要](../2026-10-workspace-ui.md)。阶段证据见 [S2/S3 验收](2026-10-25-workspace-ui-s2-s3-verification.md) 与 [修复验收](2026-10-26-workspace-ui-release-fixes-verification.md)。

## 1. 目标与决策依据

将普通用户工作区迁移到用户指定的整合版 HTML 的视觉与页面组织方式：以笔记为起点，左侧安静的导航与最近记录，中间聚焦阅读、编辑与对话，需要时在右侧查看关联资料。强调色统一为 `#266FE1`。

视觉主稿：[2026-10-23-整体UI-DeepSeek与Codex整合版.html](../../../design-preview/2026-10-23-整体UI-DeepSeek与Codex整合版.html)。本文编写时 SHA-256 为 `079a21d0269eee41283d6e7bdea3320038388fa74dc92522330f86ff301ffba8`。配套说明见 [设计说明](../../../design-preview/notewithai-unified-design-notes.md)。主稿及其模拟数据保持不变。

用户已确认：先写 Spec；保留现有真实业务，迁移视觉和必要的页面交互；HTML 中额外的业务功能单独列出，不默认全部加入。用户进一步明确：**整个管理后台不参加本次更新**，登录、注册、重置密码也排除。

采用此前建议的分阶段方案：先统一公共工作区，再交付完整的笔记流程作为视觉样板，随后迁移对话、灵感、个人页与设置，最后统一验收。直接一次改完会把视觉偏差与业务回归混在一起；完全分给子代理各自改页又容易产生不同的导航、弹窗与编辑状态。主代理负责公共组件和整合，子代理负责互不重叠的页面模块。

### 依据的优先级

1. 用户确认的范围和本文批准后的明确约束。
2. 现有真实业务契约、数据格式、可靠性与权限规则。
3. 指定 HTML 的视觉、布局、层级及适用的交互。
4. 旧 `DESIGN.md` 中不与本次设计冲突的通用原则。

实施时旧版 `DESIGN.md` 的顶部导航、旧色板和旧列宽由本次主稿替代，迁移时已同步更新。现行设计和架构约定以根目录规范为准；本历史 Spec 不覆盖其后续修订。中文、桌面优先、内容优先和可访问性原则保留。

## 2. 范围与不做事项

| 对象 | 本轮处理 |
| --- | --- |
| `/` | 保持进入 `/notes` 的默认行为；落地后展示新工作区 |
| `/notes` | 笔记首页、快速记录、独立阅读状态、编辑状态、拟标题、删除确认、相关笔记 |
| `/chat` | 普通新对话、笔记开场、已有会话、历史查找与删除、消息、来源快照、相关笔记 |
| `/inspiration` | 研究入口、内容与来源、历史分页、收藏/取消收藏、不感兴趣/恢复、定期发现与未读状态 |
| `/profile` | 真实资料、头像、统计、AI 画像及其状态、编辑资料、已登录用户修改密码 |
| 工作区公共层 | 侧栏、页内顶栏、账户菜单、上下文设置、按钮/菜单/弹窗/抽屉/提示、工作区主题 |
| `/auth` 所有模式、`/login`、`/register` | 排除；页面外观、表单、认证跳转沿用现状 |
| `/admin` 及所有子路由，包括 `/admin/login` | 全部排除；不更改后台导航、页面、业务和主题 |

已登录用户的“修改密码”是工作区内既有账户功能，迁移其弹窗样式和位置；它不等于排除的“忘记密码/重置密码”认证流程。

本轮不重写后端、不更换编辑器、不迁移笔记存储格式、不改变模型/提示词/检索/调度算法、不增加移动端产品形态、不发布上线。新增 API、数据库字段或跨账户数据迁移不属于默认实施范围；发现确实需要时先记录具体阻碍和方案。

失败判定包括：只换配色但仍保留旧页面构图；为还原演示而用本地数据替换真实数据；漏掉已有业务入口；未保存内容丢失；认证页或后台被全局样式影响；在没有服务支持时显示已经生效的功能。

## 3. 页面组织与公共交互

### 3.1 工作区骨架

- 用一个持续挂载的工作区外壳承载 `/notes`、`/chat`、`/inspiration`、`/profile`。左侧为品牌、新建笔记、主导航、随场景变化的最近区、底部账户菜单；右侧为轻量页内顶栏与主内容。
- 笔记/灵感/个人页的最近区展示真实的最近记录；对话页展示真实会话列表及已有搜索、删除能力。HTML 的“五条演示记录”不能成为生产会话历史的截断上限。
- 主导航统一用“笔记 / AI 对话 / 灵感”；个人页从账户菜单进入。选中态只代表真实位置，个人页不能误选笔记。灵感未读数沿用真实查询、轮询及 `inspiration-count-changed` 更新行为。
- 侧栏折叠、窗口尺寸变化、菜单开关不重建主任务。侧栏宽度偏好可在本机持久化；不得将业务笔记、会话列表另存成一套原型数据。
- 保留侧栏“新建笔记”和首页快速记录两个不同情境入口，进入同一个创建流程。其余重复新建按钮收敛。原型没有真实服务支持的更多菜单项不占位。
- 最近笔记来自现有笔记查询缓存；非笔记页可加载轻量数据，但不得为渲染侧栏提前加载 Tiptap 编辑器，也不得与笔记页维护互相矛盾的列表。

### 3.2 路由、返回与选中状态

本次不要求新的后端页面。笔记首页、阅读和编辑可以由同一 `/notes` 页面承载，但用户必须能清楚区分三种状态。

- `/notes` 为列表；沿用现有 `/notes?highlight=<noteId>` 作为指定笔记的阅读入口，兼容消息来源、相关笔记及旧链接。列表点开笔记后 URL 也反映该笔记，刷新可重新读取它。
- `highlight` 指向尚未加载到列表中的笔记时，继续通过既有单篇读取能力加载；不要求用户先翻完历史页。已删除、无权限和请求失败各自给出正确提示与返回入口。
- 编辑是阅读之上的显式状态；取消回到该笔记阅读，保存成功采用服务端返回版本。新建入口跨页时可以使用可消费的前端意图参数，具体命名由实施计划确定，不另造业务路由。
- 从列表进入阅读再返回时，恢复当前列表的已加载范围和滚动位置。来源跳转保留既有聊天往返记录，返回正确会话、草稿和阅读位置。
- 普通进入 `/chat` 仍默认新对话；只有用户主动选择历史或消费既有来源返回记录时恢复会话。侧栏改版不得改变此规则。

### 3.3 未保存与弹层

应用内所有会离开或替换当前笔记编辑器的动作——主导航、最近笔记、新建、阅读返回、相关笔记、发起对话、退出登录——统一经过编辑保护。

| 分支 | 必须发生的结果 |
| --- | --- |
| 保存并继续 | 等待真实保存成功再执行目标动作；失败或版本冲突保留编辑器和本地文字，不跳转 |
| 放弃修改 | 只放弃当前未保存修改，再执行目标动作；不删除已保存笔记 |
| 继续编辑 | 取消目标动作，回到原编辑器并保留输入与焦点 |

保存请求期间不重复提交。同一条笔记只存在一个活跃编辑会话；迟到请求不能覆盖已经切换的编辑器。保存期间再次输入的内容不能被旧保存结果清空。

浏览器后退/前进同样不得静默丢失修改；具体拦截与恢复机制在计划中结合 Next App Router 验证。刷新、关页和离站使用浏览器原生未保存提示，不承诺定制原生提示文字。现有新建草稿恢复继续有效；已保存笔记编辑的跨刷新持久化恢复不在本轮新增范围，界面不能对此作出承诺。

设置覆盖在当前任务上方，打开和关闭不视为离开编辑。设置、资料编辑或密码弹窗可以嵌套，但只允许最上层响应 Escape、遮罩与焦点循环；关闭后焦点回到触发按钮。业务页保持挂载，聊天流可以继续更新原会话。可编辑弹窗内部关闭也要保护其未提交输入。

## 4. 视觉系统与适配

从 HTML 提取语义 tokens，并只作用于工作区根节点及其弹层容器。不得直接复制原型的全局 `body`、`button`、`h1` 重置到整个应用；避免设置 `html.dark` 等方式连带改变认证与后台。弹层即使 portal 到外部容器，也必须获得工作区对应的主题和 tokens。

| 项目 | 新工作区约定 |
| --- | --- |
| 字体 | 系统无衬线，沿用主稿的系统字体栈与中文 fallback；代码使用等宽字体，不引入在线字体 |
| 字号 | 元信息 12px，次级控件 13px，常规 UI 14px，一般文字 15px，笔记/回答正文默认 16px，页面标题 26px，开场大标题 28px |
| 行高 | UI 1.5，一般文字 1.65，长文 1.8；阅读与编辑的正文节奏一致 |
| 间距 | 4px 基准，统一使用 4/8/12/16/20/24/28/32/40/48/64px 的尺度 |
| 圆角 | 6/8/10/12/16px；对话输入容器 26px；胶囊与头像使用全圆角 |
| 浅色 | 主画布 `#ffffff`，侧栏 `#f9f9f9`，次级面 `#f7f7f7`；正文 `#0d0d0d`，次级 `#525252`，辅助 `#6f6f6f` |
| 深色 | 主画布 `#212121`，侧栏 `#171717`，次级面 `#2a2a2a`；正文 `#f2f2f2`，次级 `#b9b9b9`，辅助 `#9a9a9a` |
| 强调色 | 实色操作 `#266FE1`，hover `#1D5BC0`；浅色文字强调 `#1D5BC0`，深色文字强调 `#9CC0FF`；浅蓝选中背景沿用主稿 |
| 图标 | 复用现有 lucide-react；统一线性风格，常规 18px、次级 16px、主操作 20px，笔画约 1.75；不混用 emoji 作为功能图标 |
| 状态 | 分清 hover、active、selected、focus、disabled、loading、error；选中不依赖颜色单独表达，焦点可见 |
| 动效 | 120/180/240ms 的轻过渡；响应系统减少动态效果及工作区本机偏好，不用动效阻塞操作 |

布局以主稿为准：展开侧栏 260px、折叠 64px；常规阅读列最大宽度 800px、对话列 820px；右侧关联栏 330px。正文随可用空间收缩，不写死满屏绝对坐标。窗口宽度 ≥1200px 时关联栏并排；更窄桌面使用可关闭抽屉，不覆盖后丢失原内容。≤980px 的窄窗口可沿用主稿侧栏抽屉行为，属于桌面窗口缩放保障。

按钮高度、内边距、列表密度、页首留白、输入框形状、分割线与轻阴影从主稿对应组件提取为共享规则，不能每页临时决定一套。长文、短文、无标题、代码、表格、长链接和图片都不能撑破主列。普通正文目标对比度至少 4.5:1。

验收桌面以 1440×900 为主，另看 1280×800、1024×768 的窗口缩放；在 1199/1200px 检查关联栏切换，在 980px 附近检查侧栏。手机浏览器和移动应用不在本轮交付标准内。

## 5. 分模块需求与保留契约

### N：笔记

- **N1 首页：**采用主稿的页首、快速记录入口、开放列表、时间分组与轻量操作。列表从现有真实游标分页获取，不用演示记录。保留加载更多、加载失败重试与服务端更新后的缓存同步。
- **N2 顺序与名称：**当前后端按 `createdAt DESC, _id DESC` 分页，本轮保持它；分组按创建时间，不以修改时间重排已加载页面。使用“最近记录”等真实描述，不提供无法保证全库正确的“最早编辑/最近编辑”排序。总数仅来自明确的服务端统计；已加载条数不能伪装总数。
- **N3 独立阅读：**点开记录后以主稿阅读列展示正文、真实日期、编辑、更多与相关入口。标题可选；无标题正文直接开始，不补“无标题笔记”的阅读标题带。列表/侧栏可用清理后的正文开头辨认记录，不将其写回标题。
- **N4 编辑与创建：**继续使用现有 Tiptap、JSON/历史文字兼容和显式保存；将工具条、标题栏、保存/取消、焦点和状态迁移到新样式。保留目前支持的图片、链接、列表、任务、表格、代码等格式，不能降级成原型 Markdown textarea。工具栏按现有实际能力呈现，长文保存操作可到达。
- **N5 标题：**手动标题维持现有 100 字符/单行校验，AI 建议使用现有 60 字符结果约束、配额、超时及过期响应保护。只有主动操作才调用；保留替换确认/撤销等现有保护。不因主稿有标题偏好而自动填必填标题或恢复标签系统。
- **N6 保存与删除：**复用 revision 写入、冲突状态、服务端标准版本和缓存传播；失败不假报成功。删除继续真实确认、等待服务成功并更新列表与阅读态。原型的删除后短时撤销不直接迁移，因为当前删除接口没有同 ID 恢复合同。
- **N7 相关资料：**沿用现有推荐刷新与来源修订校验，呈现明确关系说明、摘要和日期；空状态与降级状态真实。点击原记录可以完整阅读，回来不丢编辑或列表位置。

### C：AI 对话

- **C1 起始与进行中：**普通新对话用主稿居中的提示、输入与可选建议；进入会话后使用连续阅读消息列与底部输入。输入框、发送/等待/失败状态及中文输入法 Enter/Shift+Enter 行为保持可用。
- **C2 历史：**将现有历史面板迁入公共侧栏的对话场景；保留当前显示名称推导、按已加载消息和来源内容查找、选择、新建、删除。若搜索不是全库，应明确当前范围；不引入新的服务端搜索。
- **C3 笔记开场：**成功校验和保存绑定之后，按“原文摘录 → AI 开场身份与提问 → 输入框”的顺序显示；首问后收为紧凑来源入口。原文与 AI 提问不能混为一段，超长摘录可展开。
- **C4 本轮覆盖原型差异：****每轮仍由服务端读取绑定笔记最新保存的文字**，每条回答展示服务端自己的 `sourceSnapshot`。原型固定开场快照的实现不得迁入生产。开场历史摘录、当前讨论笔记、当轮实际依据要清楚区分；旧回答不能被新正文回填改写。
- **C5 来源往返：**保留用户/标签页隔离、30 分钟内一次恢复、异步历史等待、草稿和阅读位置恢复；用户主动换会话/发起新会话后不被迟到恢复覆盖。已删除或无权访问来源时保留会话可读性并给真实状态。
- **C6 流与持久化：**`committed` 仍是服务端保存成功的依据。接受发送立即清空输入；未提交的部分流不冒充已保存回答。保留 60 秒无数据/180 秒总时限、重试去重、适当恢复原问题、后续草稿保护、迟到响应保护和会话选择保护。UI 加载指示与原会话绑定，切换或开设置不造成重复请求。
- **C7 关联与格式：**关联栏/抽屉/计数排除绑定笔记，无其他记录不占空栏。消息继续支持当前 Markdown/GFM 表格、代码、安全链接和图片说明；每轮依据可展开查看精确版本文字。当前接口没有的多模型、多模式、重生成和反馈写入入口不照搬。

### I：灵感

- **I1 内容层级：**采用主稿的单篇阅读主区、研究按钮、为何相关、下一问题、可核验来源与历史列表。展示真实 `headline/brief/whyRelevant/nextQuestion/sources`，不把演示文章或来源混入正式页面。
- **I2 状态与历史：**保留 recent/saved/dismissed 的完整详情、服务端分页、收藏/取消、不感兴趣/恢复、查看已读、未读数同步。切换过滤和分页错误不丢当前选中内容，旧请求不能覆盖新选择。
- **I3 生成：**保留进行中、无结果、无笔记、摘要未准备好、上下文不可用、搜索服务失败、AI 失败等现有业务响应，不将全部失败写成“暂无灵感”。阻止重复生成；重试和完成采用真实返回结果。
- **I4 来源：**真实标题、站点、链接与引用编号保持对应；短摘录/展开全文沿用当前安全展示逻辑。`retrievedAt` 是检索时间，不能装成文章发布时间。无可信内容不拼造来源。
- **I5 定期发现：**沿用真实设置接口的 `enabled/consentedAt/nextEligibleAt/lastStatus/lastReason` 等状态和首次开启披露。开关成功以服务端为准，失败回到原状态并可重试；关闭定期发现不自动关闭手动研究。不复制原型独立的 `researchConsent` 本机门禁，也不承诺精确执行时刻。

### P：个人页与账户

- **P1 资料：**采用主稿的资料头、克制的统计行和分节层级。真实用户名、邮箱、现有头像预设与回退、资料保存失败提示全部保留。邮箱只读。保留账户菜单退出登录和既有会话清理。
- **P2 统计：**使用当前真实 `totalNotes/notesThisMonth`；加载失败不显示成 0，不添加不存在的对话总数、灵感总数或订阅状态。画像与统计独立加载，单项失败不能拖垮整页。
- **P3 画像：**在主稿安静的画像表面上保留现有传记、技能领域与文字级别、分析范围、时间、数据不足、历史画像、分析中、失败和恢复分析流程。技能信息说明是 AI 归纳，不引入能力分数、进度条或装饰性氛围色。
- **P4 证据边界：**现有画像 DTO 没有逐条观察对应的 noteId，不能复制主稿的“这条观察来自某篇笔记”链接，也不能临时检索几篇相近记录冒充依据。保留真实分析范围/时间说明；新增可追溯画像须另立功能。已退役话题目录不恢复。
- **P5 账户操作：**编辑资料与修改密码使用统一弹窗，复用现有校验、预设头像和请求；修改密码成功后沿用现有清理登录并返回认证页的规则。内层表单出错保留用户输入。

## 6. 设置及原型能力取舍

设置采用主稿上下文模态、左侧分类和右侧表单的构图，但只呈现本轮实际实现且可验收的选项。以下是代理的范围建议，本文批准后作为实施边界。

| 原型能力 | 本轮决定与理由 |
| --- | --- |
| 浅色/深色/跟随系统 | 纳入；属于还原主稿的必要外观能力，仅作用工作区，本机持久化 |
| 正文字号小/标准/大、减少动态效果 | 纳入；15/16/18px 用于笔记与回答正文，减少动态效果也尊重系统偏好；不写入笔记内容 |
| 侧栏折叠 | 纳入；本机 UI 偏好，跨普通页面一致 |
| 设置内账户编辑/修改密码 | 复用真实资料/密码弹窗；个人页原有快捷入口也保留，共用实现 |
| 定期发现 | 复用 I5 同一份真实状态；灵感页提供上下文入口，设置不另建第二个开关状态 |
| 默认首页自定义 | 不纳入；保持 `/` → `/notes`，无额外路由偏好产品需求 |
| AI 语气、多种聊天模式/模型、自动命名开关 | 不纳入；没有对应的用户级服务合同，不能只切换文案 |
| 关闭回答来源 | 不纳入；保留真实来源可回溯能力，可折叠详情但不隐藏依据身份 |
| 全局搜索/Cmd+K、笔记排序选项 | 不新增；保留既有对话历史查找，见 N2/C2；不能用部分缓存冒充全库能力 |
| 编辑草稿跨刷新恢复 | 保留已有新建草稿恢复；已有笔记编辑只承诺未保存保护，不复制原型全量本地数据库 |
| 保存 AI 回复为笔记、笔记副本、会话重命名/重生成/反馈 | 本轮不新增；当前页面没有这些完整动作，不用模拟动作补齐 |
| 笔记删除撤销、批量清空会话、完整数据导出 | 不纳入；当前接口不保证恢复/原子批量/全量读取的完整语义 |
| 修改邮箱、订阅支付、账户注销 | 不纳入；没有相应生产闭环 |
| 恢复演示、示例记录、模拟登录退出/更新检查 | 不出现在正式工作区 |
| 关于/隐私/条款 | 只链接现有正式内容；没有真实内容时不生成占位弹窗或编造版本 |

建议设置按实际内容收敛为“外观 / 灵感 / 账户”，不为保持原型五类而留下空分类。设置中的说明须使用真实产品文案，删除“单文件模拟、本地演示”等预览限定语。偏好只说明保存在当前浏览器，不暗示跨设备同步。存储不可用时仍可临时生效并给出适当提示。

## 7. 实现结构与协作边界

沿用 Next.js App Router、React、TypeScript、SCSS/CSS Modules、React Query、Tiptap、lucide-react 和现有 hooks/services。HTML 是设计来源，不将其整段脚本、全局状态或手工 DOM 路由植入 React。

建议通过不改变 URL 的工作区 route group/layout 组合公共外壳，将认证和管理路由留在外壳之外。实施计划决定准确目录与文件名，但需要遵守：

1. 公共层负责导航、主题/偏好、弹层容器、统一未保存导航入口、可注入的场景侧栏槽位。
2. 各页面/业务 hooks 继续拥有保存、流、选择和异步状态；外壳不创建第二套会话或编辑器状态。页面可向外壳登记导航保护和上下文，不复制业务请求。
3. 笔记缓存按真实用户隔离，沿用服务端返回值及 revision；会话历史与当前选择仍由现有会话 hooks 管理。
4. 富文本编辑器继续懒加载；侧栏、设置或个人页不得把编辑器打入所有初始包。通用菜单、按钮、对话框和关联行先定义共享样式与接口，再分模块使用。
5. 需要修改根 layout/globals/共享原语时，只添加作用范围清晰的必要内容；实际回归排除路由，不以“没有编辑它们的文件”代替验收。
6. 修改带有维护约定的源文件时，同步更新开头注释及所属 README；阶段完成同步 `DESIGN.md`、页面说明和验证记录。

实施时以包含既有配套业务的源码快照为基线，分别核对迁移增量和原有功能；本次最终版本已完整提交并发布。本条记录当时的归因边界，不是待执行的工作树操作指令。

## 8. 验收方法与通过条件

### 8.1 视觉验收

以主稿的浅/深色 tokens、几何尺寸与组成关系为依据；使用同尺寸浏览器、相同或等价长度的内容并排比较，不拿演示短文和真实长文直接判断高度是否相同。

最低截图集：笔记首页（含短/长/无标题）、阅读、编辑及未保存弹窗、普通对话起始、笔记开场、进行中会话与来源、关联栏/抽屉、灵感正文与历史、个人页、设置。主桌面浅色覆盖全套，深色覆盖所有页面和代表性弹层；窄桌面覆盖实际布局分支，不要求为每个窗口重复全套。

检查顺序：整体构图与宽度 → 字体/行高/内容节奏 → 留白/对齐/圆角/图标 → hover/selected/focus/disabled/loading/error。主稿与生产有业务差异的地方必须记录原因，不能将漏做解释为“风格接近”。不要求让真实数据、原生控件或富文本工具条与模拟数据像素一致。

### 8.2 功能验收场景

| 编号 | 必须通过的场景 |
| --- | --- |
