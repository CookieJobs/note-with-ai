# 个人中心改版设计规格

**日期：** 2026-09-29
**状态：** 待用户审阅
**范围：** `/profile`、个人中心相关前后端接口与数据索引
**前置决定：** 用户已批准本规格所列方向。本文件完成并经用户审阅后，才进入实施计划阶段。

## 目标与原则

个人中心以账户资料和用户笔记主题为核心。统计只突出笔记总数和本月新增；话题列表准确表示笔记覆盖量，而不把模型分数包装成兴趣百分比；现有技能领域、个人传记和氛围色继续展示，但明确说明它们来自一次范围有限的画像分析。移除个人中心每日推荐及其专属生成链路。

话题索引按单篇笔记独立生成和更新。初次启用时在后台逐篇补齐旧笔记，已有关键词或摘要可作为提取输入；缺少两者时，可逐篇调用现有 DeepSeek 接口，且输入受长度上限约束。范围切换只过滤已建立的索引，不触发 AI 请求。

## 页面结构与内容

1. **账户资料**：头像、用户名、邮箱、编辑资料和修改密码入口。
2. **精简统计**：笔记总数、本月新增。两项分别从用户笔记数据统计，互不依赖 AI 画像和话题索引。
3. **笔记话题**：默认“全部笔记”；另有“近一年”“近六个月”筛选。每个话题显示涉及笔记篇数，不显示兴趣分数或百分比。每个范围的计数只统计创建日期落在该范围内、且索引状态为成功的笔记；未完成索引的覆盖状况必须同时可见，不能将部分结果称作完整结果。
4. **AI 画像（旧画像）**：保留技能领域、个人传记、氛围色。区域标题或说明须清晰标注“基于最近一次画像分析”，并展示该次分析实际输入范围。现有分析服务最多取最近 20 篇；当实际服务输入范围为最近 20 篇时应明确写“最近最多 20 篇笔记”，不得暗示这些字段覆盖全量笔记。若字段没有足够数据，不生成技能等级或传记。

当笔记总数为 0 时，话题区显示创建首篇笔记的引导。笔记数为 1–4 时仍允许按已索引笔记显示话题；不生成或推断技能等级、个人传记。当前所选范围内没有笔记时，显示空状态和“查看全部笔记”入口。

## 数据契约

### 统计

`GET /api/user/stats` 的个人中心展示契约只要求：

```ts
{
  totalNotes: number;
  notesThisMonth: number;
}
```

`totalNotes` 是该用户全部未删除笔记数；`notesThisMonth` 是笔记 `createdAt` 位于本月起点（含）至下月起点（不含）的笔记数。统计服务报错不得阻塞账户资料、话题或旧画像加载；统计加载结束后显示可重试错误，不能永久保留 skeleton。

### 话题索引

每篇笔记有一条独立的 topic-index 状态记录，以 `noteId` 唯一定位，至少包含：

```ts
{
  noteId: string;
  userId: string;
  sourceRevision: number;
  sourceFingerprint: string;     // 主题输入字段的规范化指纹
  status: 'pending' | 'processing' | 'ready' | 'failed';
  topics: string[];             // ready 时可为空，已规范化、去重
  source: 'keywords' | 'summary' | 'bounded_content' | 'mixed';
  indexedAt: string | null;
  errorAt: string | null;
  lastSuccess?: {               // 可选旧快照；永不计入当前覆盖
    sourceRevision: number;
    sourceFingerprint: string;
    topics: string[];
    indexedAt: string;
  };
}
```

`sourceFingerprint` 是对标题、正文（按 3,000 字符索引截断规则）、`contentText`、关键词和摘要等实际话题输入字段按固定顺序规范化后计算的稳定摘要。有效索引必须同时匹配笔记当前 `revision` 和当前主题输入指纹；仅 revision 相同不足以判定新鲜，因为异步生成的摘要/关键词可能在不改变 revision 时更新。输入源规则及字段规范化必须固定并版本化；改变规则时使旧指纹失效并安排重算。

聚合仅使用当前用户拥有、revision 与指纹都匹配且 `status=ready` 的记录。每个话题的 `noteCount` 是包含该规范化话题的不同笔记数，同一篇笔记的重复关键词只计一次。话题名采用去空白、大小写/全半角等价规范化与别名去重；展示名由索引保存的规范展示值确定。计数按 `noteCount` 降序，再按展示名升序稳定排序。不得将计数换算为“兴趣百分比”。

用户级响应至少包含：

```ts
{
  scope: 'all' | 'year' | 'sixMonths';
  timezone: 'Asia/Shanghai';
  rangeStart: string | null;    // 含，按产品时区的本地日历边界
  rangeEnd: string | null;      // 不含；all 为 null，其余按产品时区的本地日历边界
  totalNotesInRange: number;
  readyNotesInRange: number;
  pendingNotesInRange: number;
  failedNotesInRange: number;
  topics: Array<{ topic: string; noteCount: number }>;
  staleSnapshot?: {
    noteCount: number;
    indexedAt: string | null;
    topics: Array<{ topic: string; noteCount: number }>;
    label: '旧快照，不计入当前覆盖';
  } | null;
  indexStatus: 'empty' | 'building' | 'ready' | 'partial' | 'failed';
  updatedAt: string | null;
}
```

对范围内每篇笔记恰好归入 `ready`、`pending`、`failed` 之一，三者总和等于 `totalNotesInRange`。`ready` 要求当前 revision、指纹匹配且成功；缺少索引记录、旧 revision/指纹、排队或 processing 均归 `pending`；只有当前 revision/指纹对应的失败才归 `failed`。状态聚合优先级为：总数为零=`empty`；全部 ready=`ready`；至少有一篇 ready，或同时存在 failed 与 pending=`partial`；全部笔记均 failed=`failed`；其余=`building`。界面进度 `X/Y` 中 X 是 ready、Y 是 total。不得把缺失、旧版或尚未处理的笔记当成无话题笔记。

当前话题 `topics` 永远只按 ready 笔记计数。若某篇笔记有成功的 `lastSuccess`，但当前输入指纹或 revision 已变化，可将其包含在独立的 `staleSnapshot` 中展示；`staleSnapshot` 只作为明确标注的旧快照，不进入 `topics`、`readyNotesInRange` 或 X/Y 的 X。旧快照展示与当前索引状态并行，且不得冒充当前结果。

### 画像与话题接口

路径可在实现计划中命名，但语义级契约固定如下：

| 操作 | 请求/响应语义 |
|---|---|
| `GET` 旧画像 | 返回独立的 `userProfile`（技能、传记、氛围色等旧字段）、`profileStatus`、`analysisError`（仅通用展示文案）、`lastAnalyzedAt`、`analysisInputNoteCount` 与 `analysisInputScope`。纯读取，绝不触发分析。缺少画像且笔记数不少于 5 时返回空画像和 `idle`，前端显示显式“生成画像”按钮；少于 5 篇返回 `insufficient_data`。新运行需持久化实际输入篇数/范围；旧记录没有该元数据时返回未知值并标注“范围未知的旧画像”，不得推算成全量或最近 20 篇。 |
| `POST` 旧画像生成/重试 | 显式排入一次全用户旧画像分析，返回 `accepted`、`profileStatus`、`reason`。笔记数少于 5 时同步返回 `accepted=false`、`reason='insufficient_data'`，不排队、不生成技能/传记、不更新时间；已有任务运行时返回 `accepted=false`。>=5 篇时排队，完成后 GET 返回新数据。失败时保留旧成功字段直到新任务成功；实际输入篇数/范围随成功结果一并更新。 |
| `GET` 话题索引 | 接收 `scope=all\|year\|sixMonths`，返回上述范围响应。读取不排入 AI 任务、不改变索引。 |
| `POST` 话题重试 | 接收相同 scope，仅把该范围内当前状态为 failed 的笔记重新排队，返回 `acceptedCount` 与 `alreadyRunningCount`；不等待 AI 完成，不重试成功/processing 笔记。 |

前端必须提供与这些操作一一对应的独立服务调用；页面以 GET 画像服务获得数据/状态/更新时间，重试按钮调用 POST，再按状态轮询或刷新 GET。身份验证和用户隔离沿用现有 `/api` 认证约定。准确 URL 命名留给实施计划决定。

### 输入和 AI 调用约束

索引优先使用笔记已有 `keywords` 和/或 `summary`。这两个字段缺失或都为空时，允许使用现有 DeepSeek 客户端对**单篇**笔记提取主题；不得将所有笔记正文拼接后发送。该单篇请求输入由标题及正文组成，总长度上限为 3,000 个 Unicode 字符，超出部分按字符边界截断。提示词要求返回主题标签数组，不要求兴趣评分、技能等级、传记或其他个人推断。失败按笔记记录，不阻塞其他笔记。

每个工作任务捕获 `sourceRevision` 和 `sourceFingerprint`。成功或失败写回前，必须重新读取笔记并同时比较当前 revision 与重算后的输入指纹；任一不同，旧任务不得写入当前状态或覆盖最近成功快照，并重新排队最新输入。此规则覆盖异步 AI 对摘要/关键词的更新，即使用户 revision 未变化。成功结果仅能在双重比较通过时成为当前 ready 记录；旧成功结果可保存在 `lastSuccess`，但只能作为旧快照。笔记删除时删除其索引记录；修改主题输入字段时只使该笔记索引失效并重算。

## 覆盖范围、初始化和增量更新

- 新笔记创建或相关 AI 元数据生成/更新后，为该笔记排入索引；改变相关内容只重算该篇；删除笔记移除对应索引。revision 或主题输入指纹变化任一项都使当前索引过期。各笔记任务相互独立，单篇失败不得中断队列。
- 首次部署时后台扫描旧笔记，按篇排入补齐任务。扫描和补齐不在用户请求内同步执行；前端可在整理期间继续展示已成功索引的缓存结果，但必须标识 `X/Y`。
- 后台补齐具备可恢复游标或等价断点，重复执行需幂等；不能重复增加计数。该过程不得重跑现有整用户画像分析。
- 范围筛选由服务端对笔记 `createdAt` 做日期过滤，再聚合该范围内索引；切换范围只发起读取请求，不触发 DeepSeek，也不重建索引。
- 过滤条件只依赖笔记创建时间；后续编辑笔记不会改变它所属的时间范围。

## 时间范围和时区

所有日历范围使用固定产品时区 `Asia/Shanghai`，避免部署机器时区改变统计结果。筛选边界按日历月计算：

- `all`：不设置起点或终点，统计用户所有笔记。
- `year`：从当前本地日期往前推 12 个日历月所得日期的零点（含），到下一个本地日历日零点（不含）。
- `sixMonths`：从当前本地日期往前推 6 个日历月所得日期的零点（含），到下一个本地日历日零点（不含）。

若回推目标月份没有对应日，则夹到该月最后一天。时区边界转换为 UTC 时间戳后用于 MongoDB 范围查询。`all` 范围不设时间边界；其他范围的 `totalNotesInRange` 和索引覆盖统计均使用同一组边界。界面展示的时间也按 `Asia/Shanghai` 格式化。

## 画像边界和少量笔记行为

全量话题索引是独立于 `UserProfile.interests` 的数据来源。旧 `interests[].score` 仅是旧模型画像字段，不得作为新话题计数、话题顺序或百分比的依据。旧画像分析可能少于 5 篇时无输出、且最多读取最近 20 篇；UI 应以 `lastAnalyzedAt` 及对应分析输入范围说明其新旧程度和覆盖限制。

0 篇：提示创建首篇，不触发无意义的话题提取或技能/传记生成。1–4 篇：照常排入逐篇话题索引；旧画像区域不生成技能等级或传记，POST 明确返回 `insufficient_data` 且不修改 `lastAnalyzedAt`。GET 永远不自动触发分析；有至少 5 篇时用户通过按钮显式触发。若用户删除笔记后降至 1–4 篇，原有技能/传记等推断不得继续显示为当前有效画像：将旧结果置于清晰标注的“历史画像快照”状态，并解释当前笔记不足，或隐藏推断字段并给出该解释；不得将旧数据混入当前画像。达到至少 5 篇后再次显式成功生成，才恢复当前画像展示。新分析仍最多取最近 20 篇。

只有真实成功生成并提交新的画像结果时才更新 `lastAnalyzedAt`。`insufficient_data`、排队、运行、失败及“无足够数据而不生成”的完成分支均不得更新时间戳；尤其不得沿用 `markAnalysisReadyWithoutProfileUpdate` 的旧行为把时间改为当前时间。

## 失败、缓存和重试状态矩阵

| 区域/状态 | 页面行为 | 恢复方式 |
|---|---|---|
| 话题首次整理中 | 显示成功缓存的话题和“已整理 X/Y 篇”；若无缓存，显示整理进度，不显示空话题完成态 | 后台逐篇继续处理 |
| 话题部分失败且有上次成功缓存 | 保留并显示最近一次成功的话题结果；标注失败篇数/最近失败时间；可重试失败项 | “重试失败笔记”只重试失败记录 |
| 话题失败且无成功缓存 | 该区域独立显示加载失败和重试入口 | 用户重试或后台重试 |
| 统计请求失败 | 结束统计 skeleton，显示统计暂不可用和重试入口 | 只重试统计请求 |
| 旧画像分析运行中 | 保留既有成功画像缓存；展示分析中状态 | 后台完成后刷新画像区域 |
| 旧画像失败且有成功缓存 | 保留旧画像；显示最近失败时间和重试入口 | 仅触发旧画像重试 |
| 旧画像失败且无成功缓存 | 画像区域独立显示失败和重试入口 | 仅触发旧画像分析 |
| 旧画像不足 5 篇 | 隐藏当前画像推断；如有旧成功数据则作为标注的历史快照显示，并解释笔记不足；无旧数据则显示笔记不足说明 | 达到 5 篇后由用户显式触发生成 |

失败不得泄露模型响应、堆栈、供应商密钥或内部错误文本；面向用户的文案使用可理解的通用说明，必要信息限制为“失败时间”和“重试”。话题、统计、旧画像、账户资料各自加载、错误和重试，不得因一个区域失败清空或遮挡其他区域。

## 账户头像契约

编辑资料提供 8 款随应用本地打包的预设头像，视觉上不带性别暗示，并提供“姓名首字母”默认选项。用户可在编辑资料中预览并单选；选择只保存在弹窗草稿，点击保存后才写入，取消或关闭不保存。编辑界面不提供上传文件或输入外部 URL 的控件；新头像选择只能引用应用内预设标识或首字母选项。

为兼容已有 `User.avatar` 字符串 URL：已有自定义 URL 在用户未主动选择预设前继续显示，且不得因用户名保存、打开/取消弹窗或其他资料更新而被自动改写。服务端读取仍接受并原样返回历史 URL。用户主动选择首字母或预设并保存后，存储为明确可识别的预设值（例如 `preset:<id>`），而不是远程 URL。渲染端识别预设标识；历史 URL 仍按原有方式渲染。未知的非空历史值保留原值并按旧头像回退展示策略处理，禁止自动清空。未来若实现头像迁移，应另立规格。

## 每日推荐移除与兼容性

删除 `/profile` 页面上的每日推荐 UI、用于该页面的 feed 客户端 DTO/请求、`GET /api/feed` 中的最近笔记回退列表和基于画像兴趣的推荐生成逻辑。`POST /api/feed/analyze` 只负责旧画像显式分析的功能应迁移到语义清晰的 profile-analysis 路由（保留现有触发语义、状态和响应字段），前端改用新路由。移除 `GET /api/feed` 后，旧版客户端访问会得到常规 404；应用不承诺跨版本的旧 feed API 兼容，部署前后端应作为同一版本发布。

此移除只针对个人中心“每日推荐”。笔记详情中的语义相关推荐、`/api/recommend`、笔记 `recommendCache`、笔记 enrichment 的 recommendation artifact 和相关后台管理不属于此功能，不在本规格删除范围。

## 验收场景

1. 有任意数量笔记时，统计只显示总笔记和本月新增，且值与同一产品时区边界下的数据库计数相符。
2. 每个范围返回正确的本地日历日期边界；月末回推、范围起止零点以及跨 UTC 日期的笔记均按 `Asia/Shanghai` 正确归类。
3. 同一笔记含重复关键词只给对应话题计数加一；话题按篇数降序和名称稳定排序；UI 不出现兴趣百分比。
4. 首次索引期间显示 `X/Y` 且仅展示成功记录；全部成功前状态不是 `ready`。重复运行补齐不会重复计数。
5. 切换“全部笔记/近一年/近六个月”只读取索引并过滤结果，不产生任何 AI 请求。
6. 新建/修改/删除笔记分别新增索引任务、仅重算受影响笔记、删除该笔记索引；旧 revision 任务不能覆盖新 revision 结果。
7. 对缺少关键词和摘要的单篇笔记，DeepSeek 输入不超过 3,000 Unicode 字符；请求不包含其他笔记正文。已有关键词/摘要时不为该篇调用 DeepSeek。
8. 0 篇展示首篇引导；1–4 篇有话题但不生成技能等级/传记；当前范围无笔记时提供切换到全部笔记入口。
9. 旧画像区显示其最近更新时间和最多 20 篇/实际范围说明；它不影响话题覆盖数，旧兴趣分数不显示为新话题百分比。
10. 话题部分失败有缓存时保留旧成功结果并显示失败时间和重试；无缓存时显示本区错误。统计失败后 skeleton 消失且可单独重试。任一失败不清空其余区域。
11. 新账号可选 8 款本地预设或首字母；预览、单选、保存、取消行为符合契约。历史 URL 账号只打开或取消编辑时头像仍显示，保存用户名时 URL 不被改写；主动选择新预设后存储标识并显示预设。
12. `/profile` 不调用每日推荐接口、不显示每日推荐；旧画像更新使用迁移后的画像分析接口。笔记详情语义相关推荐仍正常存在。
13. 头像选项可仅用键盘聚焦和单选，选项有可访问名称及选中状态；屏幕阅读器能区分 8 款预设与姓名首字母选项，预览变化随选择更新，取消/关闭不会保存。
14. `GET` 旧画像不触发分析；缺少画像且 >=5 篇时显示显式生成入口，1–4 篇时 `GET` 显示 `insufficient_data`。对 1–4 篇发起 POST 返回 `accepted=false`/`insufficient_data`，不生成技能/传记且 `lastAnalyzedAt` 不变。
15. 用户从 >=5 篇删减到 1–4 篇后，旧技能/传记不再作为当前有效画像展示，只能作为带历史快照标签和笔记不足说明的旧数据，或隐藏并说明原因；再次达到 >=5 篇且显式生成成功后才显示为当前画像。无数据和 1–4 篇时绝不因 GET 自动生成。

## 明确非目标

- 不重做整套用户画像算法，不扩展旧画像输入窗口，也不将旧 `interests.score` 重解释成精确概率。
- 不新增画像类别、目标推荐、外部内容推荐、排行榜或用户自定义话题维护。
- 不删除笔记详情的相关推荐、推荐缓存或笔记级 enrichment。
- 不实现头像上传、远程头像 URL 输入、第三方头像服务或历史 URL 的批量迁移。
- 不增加用户可配置时区；本规格范围统一按 `Asia/Shanghai`。
- 不改动与 `/profile` 无关的导航、笔记编辑体验或统计分析页面。

## 待实现计划阶段确认的接口选择

本规格定义了语义和响应字段，但未规定最终 topic-index 的物理存储形态（独立集合或笔记内子文档），也未固定 profile-analysis 新路由的具体路径名称。实施计划应结合现有路由、队列和索引模式确定这些实现细节，并在不改变本规格数据契约和可观察行为的前提下落地。
