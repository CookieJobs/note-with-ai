# 桌面改版审查问题修复 Spec

日期：2026-10-16。状态：独立审核通过，R1–R8 已实施并验收。

## 目标与范围

修复本轮桌面审查确认的 7 类问题，并处理个人中心错误的主导航选中状态。保留当前平直导航、开放笔记行、安静的聊天侧栏和关联参考栏。

验收以电脑浏览器为主。不新增手机适配、后端搜索、数据迁移、AI 调用、移动应用或新产品流程。既有可选标题、无标签和来源快照功能继续有效。工作区已有大量并行改动；仅做本 Spec 必需的增量修改，不重置或批量提交其他工作。

## 当前基线

依据：本聊天的桌面审查报告及 3 项隔离组件复现。审查后，另项改动已将笔记保存改为白字蓝底、取消改为深字中性底；R3 仍须验收，但不重复实现已满足的行为。其余需求实施前以实际源码和测试重新确认。

## 功能与显示要求

### R1：聊天输入法确认与发送分离

- 当 Enter 的原生事件 `isComposing` 为 true，或 `keyCode` 为 229 时，不拦截输入法确认，也不调用发送。
- 正常 Enter 仅在非 loading 且输入非空白时发送一次；Shift+Enter 保留换行。
- 保留输入框内容、自动高度、发送按钮和流式状态行为。用组件测试验证，不向真实聊天服务发送测试消息。

### R2：无标题笔记可用键盘进入编辑

- 阅读态的无标题笔记在操作区提供原生 button，名称和 tooltip 为“编辑笔记”，可通过 Tab 到达并用 Enter/Space 激活。
- 进入既有统一编辑器，不新建第二套编辑状态；标题仍可选，不恢复“点击添加标题”等阅读占位。
- 已有标题继续作为编辑入口。阅读态正文可能含链接、图片，不能把整个富文本区域粗暴包装成 button。
- 取消保留既有丢弃编辑逻辑；自动测试只在本地渲染样本上操作，不修改真实笔记。

### R3：保存与取消的可用状态清楚

- 保存使用白字实色蓝底（当前 workspace accent）；取消使用清楚的深色文字和中性背景/边框。
- 禁用与可用状态可辨，键盘焦点可见。去掉操作按钮遗留的浅青渐变、玻璃模糊和重阴影。
- 快速记录与已有笔记的按钮保持同一交互语言。当前代码已满足的部分直接验收，不另造视觉方案。

### R4：聊天历史按内容查找，并给通用标题提供可区分名称

- 只搜索当前已加载的 sessions，不新增后端接口；查询 trim 后不区分大小写的子串匹配。空查询恢复全部，输入查询不切换当前会话。
- 匹配：原始会话标题、显示名称、全部消息 content，以及会话级和消息级 relatedNotes 的 title/excerpt/content。
- 有明确自定义标题时优先使用它。空标题、“新对话”、“新会话”视为通用标题。
- 通用标题的显示名称依次取：有可读文字的来源笔记（care_source 优先，其次其他来源）、首条非空用户消息、首条非空助手消息、最后“新对话”。使用现有来源显示规则处理无标题来源；不把“查看原笔记”等无内容占位当作具体话题。
- 从消息/来源内容生成的备用名称整理空白、最多 48 个 Unicode 字符，过长加省略号；完整会话仍可打开。名称不写回服务器，不改变会话 ID、顺序或选择状态。
- 列表、删除 aria-label 与 tooltip 使用一致显示名称。搜索“飞书”能找到当前真实样本中讨论飞书笔记的通用标题会话。

### R5：推荐兜底状态的 CTA 文案真实

- 有非空 noteId 时保留“从这条笔记聊起”；无来源 noteId 时显示“开始聊天”。
- 按钮继续调用既有 onSend(aiOpening, intro)，不隐式跳转、不创建虚构来源。
- 空笔记成功响应和请求失败的通用开场白都遵守上述规则；保留原有来源可点击行为。

### R6：需要辨读的辅助信息与功能入口清楚

- 聊天推荐来源链接、刷新图标，以及灵感历史日期/状态、来源站点，使用 workspace muted（#666b73）或更深的对应文字色。
- 保持当前字号与层级，不把次级信息变成主标题；可用入口不能默认像禁用。白底文字目标对比度至少 4.5:1。
- 不全局替换所有浅灰色：禁用、占位骨架、装饰线、焦点轮廓按原职责处理。此前未实际显示的数字徽标不扩入本轮。

### R7：灵感来源先给短摘录，保留完整访问

- 每个来源默认显示最多 220 个 Unicode 字符的清洁摘录，超出加省略号；整理空白、常见 Markdown 标题/反引号/链接/强调等格式标记，不调用 AI 重写事实。
- 当原文过长或包含被清理的格式时，显示“展开来源摘录”按钮；展开后以安全纯文本、保留换行的方式显示原始 snippet，并提供“收起来源摘录”。不执行 HTML，不把来源作为可执行内容。
- 控件是原生按钮，具有 aria-expanded 和 aria-controls。短纯文本不增加多余控件；空摘录不生成空段落。
- 每条来源独立展开；切换到另一条灵感后恢复折叠，避免共享来源 ID 导致状态串用。
- 来源标题、站点、原文链接与正文引用编号保持可用。长词/URL 不撑破阅读列。原文内容和 URL 不修改、不丢弃。

### R8：不属于主导航的页面不伪装成“笔记”

- /profile 等未匹配路由不绘制任一主导航选中下划线，不声明 aria-current。
- /notes、/chat、/inspiration 及其子路径仍显示对应选中状态；未选中的主导航继续可跳转。

## 实现边界

- 输入修复在 ChatInputArea；无标题入口在 ModernNoteCard，按钮样式复用现有操作区。
- 聊天历史的显示名称与匹配提取到小型纯函数工具，供面板和测试共用，避免组件里复制遍历规则。
- 来源摘录由小型独立组件负责展开状态，纯函数负责清理/截断。保持现有 inspiration API 和数据结构。
- 不安装新依赖。不为简单颜色修改写镜像实现的单元测试，以浏览器计算颜色和实际截图验收。

## 验证与完成标准

1. 独立 sub agent 审核 Spec，解决阻断/重要歧义并记录结论后才实施。
2. 行为修复先写预期测试，观察正确原因的失败，再最小实现；已满足的 R3 记录为基线已修复并实际验收。
3. 针对 IME/229、正常 Enter、Shift+Enter、loading/空白输入；无标题入口；会话/消息两级来源搜索与通用名称；有/无来源及失败 CTA；来源清理/完整展开/切换重置；profile 与子路由选中状态做回归。
4. 前端完整测试、类型检查、改动文件 ESLint 与 diff whitespace 检查通过。发现并行改动引起的既有失败时明确定位，不能声称全绿。
5. 桌面浏览器检查已有笔记编辑、聊天搜索和推荐、灵感长来源摘录、个人中心导航；保留截图及颜色证据。边界样本用隔离组件，避免真实数据写入或 AI 调用。
6. 根 agent 验收 R1–R8，记录未解决项与限制。Spec、计划、审核记录和执行进度均落盘，支持中断后继续。

## 额度中断续跑（执行保障，不属于产品功能）

若当前应用允许，设置回到本聊天的定时续跑：读取本 Spec、计划和进度记录，只继续未完成任务，执行中的任务不重复启动；额度暂不可用时等待后续调度，不绕过额度，也不消耗重置权益或购买额度。全部验收后停止该续跑。

该机制不承诺精确在五小时额度恢复瞬间触发，依赖应用调度、本机可用和账号额度。若工具不支持，则保留断点记录并说明，不为此构建额外守护程序。
