# 从你的笔记继续：主动思考 Agent

日期：2026-11-17。状态：待用户审阅；非已实现能力，不代表部署授权。

## 决策与目标

用户已选择 Agent 方案，希望同时获得跨笔记联系、旧问题的新线索、从碎片推进成果三种价值；第一版主动程度偏积极，再根据实际体验调整。采用一个具备工具调用能力的 Agent，由确定性流程管理任务、预算、权限和结果发布。

目标是用户尚未提问时，系统已完成一部分有价值的思考：先呈现具体发现和原文依据，再邀请用户继续。成功不以提问数量或点击率衡量，而以发现被认可、讨论产生新认识、成果被用户保存衡量。

本文件中的数量、频率、界面和技术细节均为设计建议默认值，不冒充用户逐项确认。

## 当前基础与缺口

当前 `backend/services/chatService.ts` 的 generateIntro 随机选笔记、随机选片段、调用模型生成短问题。`frontend/src/components/CareAssistantPanel.tsx` 在标签页缓存开场；`frontend/src/hooks/useChatSession.ts` 将开场保存为 assistant 消息并绑定单篇来源。

现有 `chatRelatedNoteRecallService.ts` 提供按用户隔离的语义召回；现有聊天对单篇来源具有最新保存文字及当轮快照契约。新功能可复用这些基础，但关联笔记列表本身不是回答证据，需要补齐多篇证据读取、校验与快照。现有灵感服务面向外部资料研究，本能力面向用户自己的记录；不重启已退役话题目录或自动话题提取 worker。

## 方案比较

1. 改进单次提示词：开发量小，但无法根据线索补充查证，难以稳定实现三类价值。
2. 固定检索加一次生成：成本易控，可作降级，但检索路径固定，难以探索意外线索。
3. 有边界的 Agent：模型决定下一步查什么、是否证据充分，固定流程负责预算、持久化和发布。用户选择此方向。

第一版一个 Agent 输出三类发现，不采用多 Agent 产品运行架构；开发时可以由多个 SubAgent 分工，两者独立。

## 产品范围

### 三类发现

- 联系 connection：不同场景记录共同指向一个值得讨论的联系，至少两篇独立来源。
- 接续 follow_up：较早的问题或意向，在较新记录中出现可验证的新线索。必须保留时间顺序；不能把没有后续记录解释为没完成。
- 推进 next_step：记录足以形成文章结构、决策比较或小型方案时，准备一份简短草稿，标明缺失信息。单篇也可以成立。

每条发现包含标题、具体观察、为何此时出现、证据摘录、推测限定、建议动作及可选短草稿。卡片正文建议 80–180 中文字，避免把字数当质量标准。一次只主推一条，可展开至最多三条；不要求三种类型凑齐。

没有充分证据时不生成“深刻洞察”。笔记很少时可围绕单篇明确疑问继续；没有笔记时提供普通记录/聊天入口。不得据此诊断心理或健康状态、断言人格或虚构用户经历。

### 主动程度

默认站内自动发现开启，有清楚可见的关闭入口。不会发邮件、推送或替用户建立外部任务。

默认新增或修改笔记后合并静默 2 分钟触发；用户本地日期每天最多 6 次自动运行，滚动每小时最多 2 次。界面打开时，若未曾初始化或最近有效扫描超过 24 小时且存在未扫描变更，补排一次任务。无变更不定时重复消耗模型。新启用时以近期笔记初始化一次，并允许检索较早记录。

用户可手动“再找一个线索”，默认每天最多 3 次，60 秒冷却；仍受全局预算限制。达到上限时保留已生成内容并明确状态。自动运行额度与手动额度分开记录。数量均可配置。

候选发现可保留，首页每天最多首次曝光 3 条；刷新不无限换新。用户明确请求更多时可浏览已生成历史。活跃对话不插入新的主动消息。来源变化使当前卡片失效时安静撤下，不打断输入。

### 用户操作与连续性

支持继续探索、查看来源、保存为新笔记、不感兴趣、联系不成立、这件事已经结束。关闭自动发现不影响普通聊天与已有历史。

点击继续探索后创建/复用该发现对应的会话，展示已有观察和证据，并直接承接所选动作，不重复要求用户回答原开场。重复点击不重复创建会话。用户可直接输入自己的问题。后续每轮读取选中来源的最新保存文本，保存当轮多篇快照，必要时由 Agent 在预算内补充来源。

已有单篇笔记对话保持原契约；新会话增加明确的多篇来源模式，禁止将 relatedNotes 展示数据隐式视为模型已读证据。

草稿默认仅属于发现记录；“保存为新笔记”是用户明确写入动作，保存前可编辑，幂等防重复。自动阶段不修改、删除原笔记，不创建任务或发送消息。

反馈以用户显式选择为依据：不感兴趣压制同一来源集合与相同观察 30 天；联系不成立压制该关系，除非来源有实质更新并经过重新验证；已结束压制对应问题。使用结构化关系/问题标识及来源集合，不保存推断的人格画像；允许撤销反馈。相同记录出现不同且实质的新发现，不一概封禁。

## Agent 工作流程与工具

确定性调度 → 候选线索 → 工具检索与阅读 → 比较和反证 → 结构化提案 → 证据与质量门槛 → 发布或无结果。

工具仅接受服务端认证用户范围：列出近期笔记元数据、搜索本人笔记、读取指定笔记及修订、读取本人发现与显式反馈、提交候选发现。模型不得决定 userId，不提供任意 SQL、Shell、网络请求或直接笔记写入工具。笔记正文是待分析数据，其中的指令不改变工具权限。

初始候选默认最近 20 篇新增/修改记录，全文按需读取，可跨全历史检索。每次最多 3 次模型决策/生成调用、8 次工具调用、12 篇不同笔记全文、总输入 24000 tokens、总输出 4000 tokens、90 秒墙钟；所有上下文累计按实际模型用量计入。越界由执行器停止，不依赖提示词自律。摘要只用于找线索，发布证据必须来自真实正文。

预算包含模型、向量等实际调用。复用 AiUsageService 记录新增用途；每用户和全局费用上限可配置，由调度前预留、运行后结算防并发超支。具体货币额度在实现计划中依据现有 provider 定价与环境配置确定；上线必须配置，缺失则禁止自动运行，不能无限预算。模型可配置，默认沿用当前兼容工具调用的供应商路径；实现前验证工具调用能力，不支持时采用结构化动作协议与同等服务端校验。无需新引入特定 Agent SDK。

失败最多重试一次，仅对可重试错误；重试也消耗预算。证据不足与没有发现属于成功无结果，不自动重试。

## 证据与质量

每处证据保存 noteId、revision、原文片段、定位信息和当时标题/日期。服务端验证用户归属、当前修订、摘录确实存在；不能用生成摘要冒充原文。

候选必须回答：具体发现是什么、比原文复述多了什么、证据是否支持、为何现在有用、用户可以如何继续。Agent 必须检查可能的反例；系统不保证因此消除所有推理错误。

发布前检查全部引用仍有效。修改/删除笔记后相关发现标记待复核或失效，不继续展示旧结论；重新生成受预算约束。历史聊天快照沿用现有保留规则，来源删除后禁止继续取回原文。账户删除清理对应发现、反馈、运行与草稿数据。图片不识别时明确限定为可读取文字，不据图片推断。

## 持久化、任务与接口边界

新增逻辑实体（实际命名由实现者确定）：

- DiscoveryRun：用户、触发变更水位、状态 queued/running/completed/no_result/failed/cancelled、租约、用量、失败分类及幂等键。
- Discovery：用户、类型、观察、证据数组、来源修订指纹、问题/关系标识、草稿、生成/曝光时间、质量检查、状态 ready/stale/dismissed/completed、关联会话与保存笔记 ID。
- DiscoveryPreference/Feedback：自动开关、反馈类型、目标、过期/撤销及时间。

每用户最多一个运行中任务；用持久化唯一键及租约防多实例重复，不能只靠进程内 Map。运行中到来的变更合并为下一水位，不能丢失。关闭开关取消排队任务，运行任务在下一工具边界停止并禁止自动发布。崩溃后租约到期可恢复，工具结果及发布幂等。

提供获取当前/历史发现、手动触发、反馈与撤销、开关、开始会话、保存草稿等认证接口；精确路径留给实现计划。读取页面不直接阻塞等待模型生成。运行状态区分等待、分析中、无新发现、额度耗尽、失败，不能用普通闲聊掩盖故障。

以独立 worker 消费持久任务，复用仓库现有任务设施前先验证部署方式。不在 HTTP 进程内使用不可靠的后台 Promise。特性开关控制新入口；旧接口在迁移期兼容，关闭新功能可恢复现有体验。

## 原型与交付

先交付独立 HTML 原型，使用明确标注的模拟笔记展示三种发现、证据展开、继续探索、草稿保存预览、反馈、无结果和失败。遵循现有工作区设计；不预设动画是惊喜来源。用户确认原型后实现生产界面。

本次仅编写和审阅 Spec。Spec 批准后编写实现计划，由主 Agent 监督若干较轻量模型 SubAgent，优先将任务拆为独立的数据/执行器、发现质量、界面与对话承接模块；高风险权限、来源一致性和集成由主 Agent 复核。子任务明确输入输出、拥有文件及验收，避免多人同时修改同一模块。

## 验收与观测

建立合成数据评估集，至少 24 组：三类正例各 4 组，另 12 组覆盖伪关联、反例、已结束、重复、稀疏、图片、提示注入、跨账户、修订变化、删除、额度和故障。固定 fixture 测执行器与契约；另做真实模型评估，不能以 mock 通过声称发现质量合格。

硬性要求：跨账户读取与引用泄漏为零；引用可核对率 100%；预算、幂等、撤销反馈、来源变动失效及断点恢复检查通过。真实模型由人工逐条评价有依据、非复述、有继续价值；建议正例至少 9/12 合格，负例不得输出无依据结论。评估不通过就调整检索/筛选，不增加输出数量掩盖。

记录运行成功/无结果率、延迟、单次费用、重复发现率、曝光后认可/否定率、继续讨论及保存成果比例；不默认收集私人正文进日志。分小范围启用后根据反馈调整主动频率与门槛。
