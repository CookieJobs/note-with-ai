# P16＋P17：整理灵感与定期主动发现（联合评审草稿）

> 状态：待产品评审；不是实施授权。日期：2026-09-25。

## 目标与依据

P15 已能由用户手动生成一条有真实来源的研究灵感，并把完成的结果按用户持久化。本联合需求让用户找回、保存或忽略这些结果；用户明确开启后，系统还能定期研究新的灵感，并把新结果放进同一份历史。成功的标准是：整理状态跨设备保留，主动研究只在有效授权和频率限制内运行，用户能发现并回看新结果，服务重启不会导致重复检索或任务永久卡住。

P16 与 P17 作为**同一轮产品评审、同一份实施计划、同一个开发分支和一次整体验收**。实施可以先完成列表与状态，再接入后台任务，但不把只有 P16 的半成品当作本需求已交付，也不分两次合并。P15 仍需先完成当前体验验证；旧恢复清单中“P16 稳定后再启动 P17”的顺序由这次联合交付决定替代。

本稿依据 [P15 设计](./2026-09-21-p15-source-inspiration-design.md) 和两份恢复清单中的 P16、P17 条目。恢复清单描述的是被舍弃版本的能力及局限，不等于已经批准的产品方案。当前代码只有手动研究与最新结果接口；`InspirationItem.status` 是内部生成状态 `draft/completed`，还没有用户整理状态、主动研究授权或持久后台任务。

## 推荐方案与备选

| 选择 | 方案 | 判断 |
| --- | --- | --- |
| 页面 | 在现有“灵感”页增加历史列表及“最近 / 已保存 / 已忽略”视图；生成新结果后自动打开它 | 推荐。用户在同一处研究和回看，最新结果只出现一次 |
| 页面备选 | 另建独立收藏页 | 增加导航和页面切换，现阶段收益不足 |
| 状态 | 保留 `draft/completed` 作为生成状态，另加用户整理状态 | 推荐。避免旧版单一 `status` 混淆生成与整理流程 |
| 状态备选 | 把 `saved/dismissed` 直接加入现有 `status` | 会让“完成”和“保存”互斥，破坏 P15 的查询与去重语义 |
| 主动频率 | 用户明确开启后，每位用户最多每 24 小时尝试一次；最近一次手动研究也顺延下一次主动研究 | 推荐。用户容易理解，也能控制重复检索与供应商费用 |
| 主动频率备选 | 固定每小时的某一分钟检查并只按上次成功时间限流 | 旧版失败时可能反复尝试，且固定分钟对用户没有价值 |
| 新结果提示 | 在站内导航和灵感历史中提示未查看的主动结果 | 推荐。本期不依赖系统推送或邮件基础设施 |

## 术语与操作语义

- **灵感记录**：P15 已完成并保存的一张研究结果卡，包含整理文字及可核对的来源。只有 `completed` 记录能进入用户列表。
- **保存**：把一条灵感加入“已保存”视图，保留原有研究文字和来源。它不会自动创建笔记，也不会改写笔记。
- **取消保存**：移除保存标记和“已保存”视图中的条目；它仍留在“最近”，结果及来源仍保留。
- **忽略**：把一条普通灵感移出“最近”视图。它只整理这条记录，不代表系统学会了用户不喜欢该主题，也不阻止未来出现相近主题。
- **恢复**：在“已忽略”视图把记录放回“最近”。忽略是可撤销的，来源去重记录不因忽略或恢复而删除。
- **回看**：通过分页历史找到旧灵感并重新打开完整内容、引用和来源。打开来源仍遵循 P15 的安全外链规则。
- **主动发现**：用户主动开启后，服务端按频率限制自动执行与 P15 相同的受限笔记提取、DeepSeek 规划、Tavily 检索和带引用整理。它不读取笔记正文，也不把笔记字段发送给 Tavily。
- **新灵感**：主动生成、尚未被用户打开的完成结果。仅以站内提示计数；打开详情后标记为已查看。手动结果自动打开时也标记已查看。

推荐的状态流转：

| 当前状态 | 可见操作 | 操作后 |
| --- | --- | --- |
| 普通 | 保存；忽略 | 已保存；已忽略 |
| 已保存 | 取消保存 | 普通 |
| 已忽略 | 恢复 | 普通 |

已保存的灵感若要忽略，先取消保存，避免一次点击意外移除收藏。操作成功后才更新持久状态；请求失败时保留原状态并提示重试。重复提交同一操作应得到相同结果，不生成额外记录。

旧版把 `read` 与保存/忽略放在同一个状态字段，页面也没有形成完整体验。联合需求使用独立的查看时间表示“新灵感”；查看行为不覆盖保存或忽略状态。已忽略但未打开的结果不计入新灵感提示。

## 页面与用户流程

1. 用户进入“灵感”页，仍可看到 P15 的研究按钮和数据说明。默认打开“最近”：按生成时间倒序显示所有未忽略的完成结果，包含已保存结果。
2. 列表中的每条记录显示主题、标题、生成时间和保存标记；用户打开一条后查看完整研究卡。新生成的结果插入列表顶部并自动打开，不再在列表外重复展示同一张卡。
3. 用户保存当前灵感后，按钮状态立即明确为“已保存”，该条仍留在“最近”，也出现在“已保存”。取消保存后从“已保存”移出，但仍留在“最近”。
4. 用户忽略普通灵感后，该条从“最近”移走；若它正被打开，页面打开下一条可见结果。用户可以在“已忽略”中找回并恢复它。
5. 三个视图均支持继续加载，每次最多 20 条，列表没有“只保留 20 条”的总量限制。滚动或切换视图不自动发起外部搜索。
6. 若“最近”为空，页面解释当前没有可展示的灵感，并保留手动研究入口及“已忽略”入口；读取或更新失败时提供就地重试，不清空已经显示的内容。
7. 页面提供默认关闭的“定期为我寻找灵感”开关。开启前就地说明：使用近期笔记的标题、关键词、短摘要；DeepSeek 接收受限元数据，Tavily 仅接收搜索查询；每 24 小时最多尝试一次，结果进入灵感历史。用户确认开启时才保存授权，页面显示开关状态、预计下次检查时间和最近一次检查结果。
8. 开启本身不立即调用外部服务；第一次主动研究在开启满 24 小时后的下一次后台检查中进入调度，页面显示换算成用户本地时间的预计时间。用户想立即查看结果仍可使用手动按钮。关闭后不再启动新的主动研究；已经开始的外部请求无法收回，可能完成并出现在历史中，关闭不会清除既有结果。
9. 主动产生的新结果出现在“最近”顶部，标明“定期发现”；主导航与列表显示未查看提示。打开该条后清除相应提示。没有新来源、没有可用笔记或研究失败时不制造一张空结果卡，页面仍可查看上次检查状态。

列表和操作应支持键盘及屏幕阅读器，按钮要有清晰的当前状态与结果反馈。不同视图之间切换时保留各自的浏览位置，重新打开记录时来源引用仍与 P15 一致。

## 数据与接口边界

在 `InspirationItem` 上独立增加用户整理状态，例如 `userState: regular | saved | dismissed`、`userStateChangedAt`；再增加 `origin: manual | scheduled` 和 `viewedAt`。现有 `status: draft | completed` 不改含义。旧 P15 完成记录须作为普通、手动结果出现在历史中；实施时用兼容读取或幂等回填处理缺失的新字段，不丢失现有结果。

另设按用户唯一的主动发现设置，记录是否开启、用户明确同意的时间、上次尝试与下次可执行时间、最近结果状态。设置默认关闭。后台任务状态必须持久化，至少能区分待处理、执行中、完成、无结果与失败，并具有原子认领、租约过期处理和每用户唯一进行中约束。后台扫描和处理可以分步实现，但不得只靠进程内 `setImmediate` 或单个进程内计时器保证执行。

建议接口：

- `GET /api/inspirations?view=recent|saved|dismissed&cursor=...`：只返回当前用户的已完成记录，默认 `recent`。每页最多 20 条；“最近”按生成时间倒序，“已保存/已忽略”按状态变更时间倒序。游标由所在视图的排序时间和记录 ID 组成，返回 `items` 与 `nextCursor`，不以固定 20 条作为总容量。
- `GET /api/inspirations/:id`：返回当前用户指定结果的完整 P15 安全 DTO；不存在或属于其他用户时统一返回 404。
- `PATCH /api/inspirations/:id/user-state`：只接受 `save`、`unsave`、`dismiss`、`restore` 四种操作，检查当前状态与所有权，返回更新后的用户状态。非法流转得到稳定错误，不改变记录。
- `POST /api/inspirations/:id/viewed`：用户实际打开详情后将该条标记为已查看；重复请求幂等。新灵感计数只统计当前用户未忽略、未查看的主动完成结果。
- `GET /api/inspirations/settings`：返回当前用户的开关状态、预计下次检查时间与最近一次检查的安全状态码；默认关闭时也有确定响应。
- `PUT /api/inspirations/settings`：只接受布尔开关。开启前检查所需供应商配置是否存在并保存同意记录；关闭后阻止新的自动任务被认领。不会因读取或保存设置立刻发起搜索。
- 保留 P15 的 `POST /api/inspirations`。`GET /api/inspirations/latest` 只返回最近一条未忽略的完成结果，避免刷新后把刚忽略的卡片再次展示。

列表、详情、设置和状态接口都不得返回笔记正文、内部搜索查询、供应商密钥、其他用户的记录或未完成草稿。保存、忽略、恢复、查看及分页读取只访问本项目数据库，不调用 DeepSeek 或 Tavily。忽略不会释放 P15 的 `InspirationSource` 去重登记，否则同一来源可能立刻被再次推荐。

主动任务沿用 P15 的来源校验和每用户去重，并与手动请求共用“同一用户同一时刻最多一次研究”的持久约束。后台每次尝试至少与前次主动尝试间隔 24 小时；手动研究开始后顺延下一次主动时间，避免紧接着重复消费外部服务。调度失败、无笔记或无新来源也推进下一次时间，不会在短时间内反复消耗配额。后台自动任务建议默认最多同时执行 2 个、全站每日最多尝试 20 次，两项上限可由服务端配置调整；服务停机后恢复时只处理仍符合频率限制的任务，不为停机期间每一天补跑一次。

关闭开关后不得再发起新的 DeepSeek 或 Tavily 调用；已发出的请求不能撤回，处理程序应在下一次供应商调用前复核开关。跨进程重复调度、服务重启或租约过期时，已经进入外部调用阶段的任务在本次 24 小时周期内不重新调用供应商，避免重复花费和超频；它可以被记为失败并在下一周期恢复。

## 失败与边界场景

- 网络失败：按钮恢复可操作，显示保存/忽略未成功；用户重试不会产生重复状态。
- 多标签页同时操作同一条：后端按当前状态验证流转；过期操作返回冲突并让前端刷新该条的最新状态。
- 来源网页后来失效：历史仍显示生成时保存的来源资料与原链接，不声称链接始终可用。
- 超过 20 条：通过游标继续读取；新灵感在翻页期间插入时不重复或漏掉已存在的记录。
- 用户隔离：任何列表、详情或状态操作都必须限制 `userId`；他人的 ID 不暴露存在性。
- 现有 P15 结果：上线后出现在“最近”，无需用户再次研究。
- 授权与关闭：未开启者不产生自动外部请求；关闭时尚未开始的任务取消，执行中的任务按上述边界收尾；关闭不影响手动研究。
- 服务重启与多实例：任务不会永久停在“执行中”，同一用户不会被两个实例同时研究；重启后不会集中补跑或突破每天一次的限制。
- 供应商或配置失败：只记录受控错误码、供应商类别及 HTTP 状态，不记录搜索查询、笔记片段、密钥或完整响应。用户在设置旁看到可理解的上次失败状态；下一周期仍可恢复。
- 额度保护：达到全局自动尝试上限时延后执行并显示“等待下次检查”，手动研究不由该自动上限拦截。

## 与旧版代码的关系

弃用版本 `50956a1` 有灵感列表、保存/忽略、开关及调度代码，可借鉴用户操作与测试场景；其数据结构是单来源卡片，把 `unread/read/saved/dismissed` 放在一个 `status` 字段，列表总量限制为 20 条。旧调度每小时扫描，只在成功后更新时间，并依赖进程内执行，不能保证崩溃恢复或防止失败时频繁重试。当前 P15 是多来源研究卡，`status` 已用于 `draft/completed`，并用进程内 Map 防止同一用户的手动并发。因此旧模型、服务、页面和调度器都不能直接 cherry-pick；应按当前 P15 的研究流程建立共同的持久任务边界。

## 不纳入本联合需求

- 把保存的灵感自动转成笔记；可另行设计“以此为题写笔记”。
- 根据忽略行为调整未来检索主题或训练偏好。
- P06 的单篇笔记 AI 参与控制。
- 邮件、短信、浏览器系统推送及精确到某个钟点的用户自选日程；本期提供站内新结果提示。
- 永久删除及批量管理。永久删除与笔记删除后历史灵感的保留规则列为评审点。

## 亲自验收

1. 连续生成两条灵感，刷新和重新登录后都能在“最近”找到，并能打开各自的完整引用与来源；最新结果不重复出现两次。
2. 保存其中一条，确认它同时在“最近”和“已保存”；取消保存后只从“已保存”移走。整个过程不创建笔记，也不产生新的 AI/搜索请求。
3. 忽略另一条，确认“最近”与 `latest` 均不再展示它；在“已忽略”中恢复后重新出现，且同一来源不会因忽略被再次搜索结果复用。
4. 在测试数据中准备超过 20 条完成结果，逐页访问能看到全部记录，切换视图和新增结果不会造成重复或遗漏。
5. 使用另一账号或伪造 ID 请求，无法读取或修改第一位用户的任何灵感；异常请求不改变原记录。
6. 模拟保存/忽略失败与两标签页冲突，页面给出可恢复提示，刷新后状态与服务端一致。
7. 新账户默认关闭主动发现：经过多个调度周期也不向 DeepSeek 或 Tavily 发起自动请求。开启时能看清数据用途与频率，开启后能看到预计下次检查；关闭后不再产生新自动任务。
8. 用可控时钟跨过首次运行与下一个 24 小时周期：每周期最多一次自动尝试；无笔记、无新来源、供应商失败都不在小时级反复重试；一次手动研究会顺延下一次自动研究。
9. 自动生成的有效结果进入同一历史，带“定期发现”标识与未查看提示；打开后提示消失，保存、忽略与恢复行为和手动结果相同。无结果或失败不生成假卡片。
10. 在两个后台实例同时扫描、任务中途重启、租约过期及用户关闭开关的场景下，不出现重复外部调用、超频或永久卡住；日志与页面仅暴露安全状态。达到全局额度上限时自动任务延期。

## 请用户重点评审的选择

1. **保存的含义**：建议只收藏灵感记录，不自动转成笔记。
2. **忽略的可逆性**：建议在“已忽略”视图允许恢复；“忽略”只整理当前结果，不影响未来主题。
3. **历史保留与删除**：建议本联合需求先保留所有已生成结果；若删除一篇关联笔记，旧灵感仍作为独立结果存在。若需要彻底删除单条灵感，应把“永久删除”纳入本需求，并单独定义来源去重如何处理。
4. **主动频率与费用**：建议开启满 24 小时后首次执行，此后每用户至少间隔 24 小时；手动研究会顺延下一次主动执行。全站自动任务建议默认同时最多 2 个、每天最多 20 次。
5. **新结果提醒**：建议本期提供站内导航提示和历史中的“新”标记；邮件、短信或系统推送另立需求。
6. **查看状态**：建议用独立的 `viewedAt` 支持新结果提示，不照搬旧版与保存/忽略互斥的 `read` 状态。

以上作为一个需求整体评审。选择尚未由用户批准；评审后再为 P16＋P17 写一份联合实施计划并开始编码。
