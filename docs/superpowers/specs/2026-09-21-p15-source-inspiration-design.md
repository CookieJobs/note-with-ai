# P15：手动寻找一条有真实来源的外部灵感

## 目标与范围

已登录用户可在新的“灵感”页面主动请求一条外部网页内容。结果必须显示真实来源链接、来源标题、站点名、搜索服务返回的摘要，以及与用户近期笔记主题的关系说明。

本期仅实现用户点击后的单次手动请求。它不实现自动定时任务、通知、收藏、忽略、历史筛选、将灵感转为笔记，或“禁止某篇笔记参与 AI”的控制。这些分别属于 P17、P16、P06。

## 用户行为与隐私边界

1. 用户打开“灵感”页面，页面明确说明：每次请求只会向外部搜索服务发送一条从近期笔记标题或关键词得到的主题查询，不发送笔记正文。
2. 用户点击“寻找一条有来源的灵感”。按钮在请求期间禁用并显示进行中状态。
3. 服务端按 `updatedAt` 从该用户最近 10 篇笔记中选择第一篇具有非空标题或关键词的笔记。查询优先使用标题，否则使用最多三个关键词；去除邮箱、URL、@/# 标记，收缩空白并截断至 160 个字符。
4. 服务端以该查询调用 Brave Search Web Search API，最多读取 5 条结果。仅接受同时具有安全 `http`/`https` URL、标题和非空 `description` 的结果。
5. 服务端选择该用户此前未收到过的第一个有效来源，写入一条灵感记录并返回。页面展示该记录。
6. 用户从“查看来源”打开原始网页。页面不得将摘要、标题或模板理由表述为已阅读全文或由 DeepSeek 验证的事实。

“为什么推荐”使用固定、可解释的文案，例如“它与近期记录的主题‘时间管理’有关。摘要来自搜索结果。”不调用 DeepSeek。这样避免额外的数据外发、模型失败点和不可验证的来源归纳。

## 外部服务与配置

选用 Brave Search API 的 Web Search 端点。它返回 `web.results[].title`、`url` 与 `description`，正好是本功能需要保存和展示的来源证据。

部署环境必须设置以下仅服务端读取的变量：

- `BRAVE_SEARCH_API_KEY`：请求头 `X-Subscription-Token` 使用的密钥。
- `BRAVE_SEARCH_COUNTRY`：可选的地区参数。
- `BRAVE_SEARCH_LANG`：可选的内容语言参数。

密钥不得进入前端代码、提交记录、日志或接口响应。搜索适配器使用 8 秒超时，并只记录受控错误代码与 HTTP 状态，不记录查询文本或响应正文。

如果未配置密钥，手动请求返回稳定的 `SEARCH_PROVIDER_UNAVAILABLE`。如果 Brave 不可访问或返回非成功响应，返回 `SEARCH_PROVIDER_FAILED`。无候选、候选缺少必要来源字段或所有候选已展示过时，返回正常的 `no_result` 状态，不创建记录。

### 获取、保存与轮换 API Key

以下操作由项目负责人在 Brave 控制台中完成：

1. 打开 [Brave Search API Dashboard](https://api-dashboard.search.brave.com/register)，注册或登录账户。
2. 在控制台的 Plans / Subscriptions 页面启用 Search 计划。Brave 当前说明免费额度也需要添加信用卡作为反滥用验证；以控制台在操作时显示的计划和费用为准。
3. 打开 API Keys，选择 Add API Key，为密钥命名，例如 `noteWithAI-production`，并关联刚启用的 Search 计划。
4. 只在生成时复制密钥，将其保存到团队的密码管理器或服务器密钥管理机制中。不要把它发送到聊天、邮件、GitHub Issue、提交记录或截图中。
5. 将密钥写入生产服务器的服务端环境变量 `BRAVE_SEARCH_API_KEY`，重启后端服务使其生效；不要写入 `frontend/.env*`、公开配置或任何会被构建进浏览器的变量。
6. 部署后使用已登录用户点击一次“寻找一条有来源的灵感”进行验证。成功时页面应显示来源；未配置时应只显示“目前无法寻找新灵感”，不得回显密钥或查询内容。

密钥怀疑泄露时，先在 Brave 控制台撤销旧密钥，创建替代密钥并更新服务器环境变量，再重启后端。不要在代码中添加备用明文密钥。Brave 的认证与创建密钥步骤以其[官方认证说明](https://api-dashboard.search.brave.com/documentation/guides/authentication)和[快速开始](https://api-dashboard.search.brave.com/documentation/quickstart)为准。

## 数据与服务边界

新增 `InspirationItem`：

- `userId`
- `relatedNote`：`noteId`、请求时的 `noteRevision`、`topic`
- `source`：`canonicalUrl`、`title`、`publisher`、`snippet`、`retrievedAt`
- `whyThis`
- `createdAt`、`updatedAt`

在 `{ userId, 'source.canonicalUrl' }` 上设唯一索引。它既保证跨用户隔离，也避免同一来源向同一用户反复推荐。记录保存是 P15 的去重和刷新后继续展示所必需的基础，不提供 P16 的保存、忽略或回看状态。

新增服务分为三个单一职责模块：

- `braveSearchProvider`：验证配置、执行请求、把 Brave 响应收敛为 `{ url, title, snippet, publisher }`。
- `inspirationService`：选择并最小化主题、去重、持久化与稳定状态映射。
- `inspirationController/routes`：认证、参数边界、标准响应信封。

接口：

- `POST /api/inspirations`：创建一次手动请求，返回 `{ status: 'created', item }` 或 `{ status: 'no_result' }`；配置和供应商错误使用稳定错误码。
- `GET /api/inspirations/latest`：仅返回当前用户最近的一条灵感，或 `null`。不返回笔记正文、内部查询、API 密钥或其他用户记录。

所有写入、读取和来源去重均以认证用户为范围。P15 不读取 P06 偏好，因为 P06 被明确延后；因此本期所有近期笔记均可能参与主题选择。

## 前端

新增 `/inspiration` 页面，并在现有主导航增加“灵感”入口。沿用现有导航、页面和卡片视觉，不引入主题或全局布局改造。

页面包含：

- 简短的数据说明和主按钮“寻找一条有来源的灵感”。
- 加载状态“正在寻找一条有来源的灵感…”。
- 空结果状态“这次没有找到可展示的内容”。
- 供应商不可用和请求失败的可区分、可重试状态。
- 单条结果卡片：来源标题、站点、来源摘要、推荐理由和安全外链。

外链必须使用 `target="_blank"` 与 `rel="noreferrer"`。页面不提供 P16 的“保存”或“不感兴趣”操作。

## 测试与验收

后端测试：

- 主题只来自标题或关键词，正文、邮箱、URL、@/# 标记不会传给搜索适配器。
- 未配置、供应商失败、无结果、缺失来源字段和重复来源各有正确且不泄露细节的响应。
- 同一 URL 对同一用户只写入一次，不同用户相互隔离。
- `latest` 只返回当前用户所需的安全字段。

前端测试：

- 说明文案、加载、空结果、错误和成功卡片准确显示。
- 请求进行时不可重复提交；失败后可重试。
- 卡片只展示服务端来源字段与模板理由，外链安全属性正确。

人工验收：

1. 在部署环境设置 `BRAVE_SEARCH_API_KEY`，以一篇有标题或关键词的近期笔记点击请求。
2. 打开的外链与卡片标题、站点和摘要对应；页面不声称读取了全文。
3. 重复点击不重复展示同一来源；无配置、无结果和服务失败状态各自清楚。
4. 用另一用户访问时，不能看到第一个用户的灵感或来源记录。
5. 检查服务日志和前端网络响应，确认没有笔记正文、查询文本或 API 密钥泄露。
