# NoteWithAI 工作区版本发布计划

2026-10-26。用户已明确授权 commit、push GitHub 和上线。本计划沿用已批准 UI Spec 与缺陷修复，不增加业务需求。

## 发布范围

候选包含工作区改版、已验收的 R1–R6/P3 修复，以及其依赖的可选笔记标题、来源对话、个人画像等既有本地功能。远端 main 基础为 `58cc31f`，本地已有 22 个待推送提交；本轮不是只有 CSS 的独立前端发布。

排除本机凭据、工具记忆、实验数据、构建副本和不相关旧预览。管理后台产品代码不变；认证页仅携带迁移前已有的可访问性修复。新增后台测试修正只明确本地测试环境并守住非 development 不可免 TOTP 的条件，不改变认证实现。

## 执行与门禁

1. 完整候选审查和敏感信息检查：精确路径 staging，保留用户未提交的其他工作，不使用 reset/clean/force-push。
2. 新鲜前端全量测试与后端全量（启用隔离 Mongo 集成用例）、类型检查和构建。首轮失败保留诊断；只修正旧测试的错误前提，保留原安全/兼容断言并复审。
3. 只读确认生产版本、工作树、健康、容量和 revision。无无效 revision 时不执行回填；不启动已退役 topic runtime 或额外 inspiration worker。
4. 保存数据库 archive、配置、原提交与实际旧镜像，归档校验并 dry-run 检查数据库备份；给旧镜像独立回滚标签，禁止 prune。备份及敏感部署信息只留受限服务器目录/本机忽略的账本，不提交 Git。
5. 提交完整候选到专用分支，推送并建立 PR；核对远端基础和检查结果后合入 main。使用精确主分支 SHA 发布，保留全部历史工作。
6. 服务器先拉取并构建新镜像，构建期间旧服务继续运行；新容器编译产物/配置与临时预发布检查通过后，再切换 backend/frontend，不重建或删除 Mongo/Redis 数据卷。
7. 切换后检查容器、API、各页面和静态资源，确认现网版本。若关键健康检查失败，用原镜像/原代码和保存的配置恢复服务，保留新数据，绝不把数据库还原当作常规代码回滚。
